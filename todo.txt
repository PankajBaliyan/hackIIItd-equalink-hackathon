Module === Scan Now

1. "Auto-open PR when done" does nothing.
   auto_ship is sent by the form and accepted by ScanIn, but nothing reads it.
   POST /scans/{id}/ship returns a hardcoded 501: "Opening pull requests isn't implemented yet."
   (server/app/routes_scans.py)

2. The TrustStrip claims are not true yet.
   "every fix is a PR" is not true until PRs are built (item 1). "axe-core re-checks every fix" is now true for page scans.
   (client/src/components/scan/TrustStrip.tsx)

3. Private-address blocking is off by default.
   ALLOW_PRIVATE_TARGETS=true, so it must be set to false for a deployed server (SSRF protection).
   (server/.env.example, server/app/pipeline.py: check_target)


Done:
- Website scans were axe-only. They now also get an OpenAI review of the rendered page when OPENAI_API_KEY
  is set, and fall back to axe-only without a key or if the review fails. (server/app/page_llm.py)
- Fix generation and verification (server/app/fixer.py). Axe issues on pages get an OpenAI-proposed patch that is
  checked by re-running axe-core on the live DOM; static findings in repo scans are checked by re-running the static
  rules on the patched file. Needs OPENAI_API_KEY; without it issues are left for human review.
  Still not covered: issues found by the OpenAI review (not re-checkable), html/body-level issues, and fixes that
  overlap each other in one file (relevant when PRs are built).
- Full-site crawl (server/app/pipeline.py). scope=site now crawls breadth-first, following same-origin links on
  every scanned page, up to MAX_SITE_PAGES (default 20, was 5). A page that fails to load is skipped (fresh browser
  tab) instead of failing the scan, and pages beyond the limit are reported in the scan log.
  Still sequential (one page at a time), so large limits make slow scans; no sitemap.xml or robots.txt handling.
- Submit button label. It said "Scan with TinyFish" even when the scan fell back to local Chromium. It now says
  "Scan website"; the engine actually used is shown on the live scan page (TinyFish browser / Local browser chip).

Module === Live Scan

Working and dynamic: header chips (incl. engine used), stepper/status, live SSE agent log with reconnect +
polling fallback, severity counters, elapsed timer, pages list, sidebar link to the latest scan.

1. The score ring only shows score_before.
   The server computes the score at the end of the scan, so the ring stays "-" until then. score_after is
   not shown on this page. (client/src/components/scan/LiveScan.tsx, server/app/pipeline.py: run_scan)

2. "Pipeline progress" is a stage estimate, not real progress.
   Stage index / 6, capped at 95%. No "page 3 of 12" detail, and "N pages with issues" does not say how many
   pages were scanned. (client/src/components/scan/LiveScan.tsx)

3. The "Shipping" step in the stepper is never reached (PRs are not built, see Scan Now item 1).

4. Minor: with zero scans the sidebar Live Scan / Fixes links fall back to the hardcoded id "demo" and open
   "Couldn't load this scan". (client/src/lib/nav.ts: DEMO_SCAN_ID, client/src/components/shell/AppShell.tsx)

Done:
- Finished or failed scans now open with their stored log. New GET /scans/{id}/log returns the events as JSON and
  the store loads it for a scan that is already over, so the log, elapsed timer and the stepper stage (the stage a
  failed scan stopped in) are right. scan.error is now returned by the API and shown in the "Scan failed" banner.
  A scan with no recorded log says so instead of "Waiting for the agent...". (server/app/routes_scans.py,
  client/src/state/scanStore.tsx, client/src/components/scan/LiveScan.tsx)
- The agent log no longer duplicates after a reconnect. The client remembers the last event id it received and
  reconnects with ?after=<id>; the server's /scans/{id}/events accepts it (alongside Last-Event-ID) and only sends
  the events after it. (client/src/lib/sse.ts, server/app/routes_scans.py)
- The "Scan complete" banner now reflects the real result: "No issues found" (no button) when clean; "N issues
  found, no automatic fixes were proposed" with a "Review issues" button when there are none; otherwise
  "N issues found: X validated fixes ready to review, Y rejected by the rules engine, Z need human review" with
  "Review fixes". (client/src/components/scan/summary.ts, LiveScan.tsx)
- The screenshot panel shows the real page. Each scanned page is captured (JPEG, stored in the DB table `shot`,
  height capped by SCREENSHOT_MAX_HEIGHT=4000) and every finding that can be located gets a box (percent of the
  image, stored on the issue), drawn in its severity colour. Full-site scans get a page picker. GET
  /scans/{id}/shots/{shot_id} serves the image; a "shot" log event makes the page show it while the scan runs.
  Source scans say there is no page to show. (server/app/screenshots.py, client/src/components/scan/AnnotatedScreenshot.tsx)
  Not covered: boxes for elements inside iframes / shadow DOM or hidden elements, very long pages are cut at
  4000px, and no click-a-box-to-open-the-issue yet.
- Pages that reveal content on scroll (opacity-0 sections, lazy images) were half blank in the screenshot and axe
  judged hidden elements. render() now scrolls down the page and back before axe and the screenshot
  (server/app/pipeline.py: reveal_lazy_content; capped at 30 steps, so endless-scroll pages stop).
  Not covered: sections that hide again when scrolled out of view, and sites that need a click to show content.
- Scrolling the screenshot no longer drags the whole page. The screenshot box (and the agent log) now use
  overscroll-behavior: contain, so wheeling past either end of the screenshot stays inside it; before, wheeling up
  past its top sent the whole UI to the top. The agent log's hidden screen-reader labels were also escaping the log
  and adding 24px of blank scroll area per log line under the page; the log is now their containing block.
  (client/src/components/scan/AnnotatedScreenshot.tsx, TerminalFeed.tsx)
